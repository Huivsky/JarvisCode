# Jarvis Code 4.2.0-beta.1 — первый этап харнесса

## Реализовано

1. Критерии завершения: ручная проверка пользователем, точная команда nc_run с наблюдаемым кодом 0, наличие обычного файла до 64 МиБ с SHA-256. Критерии фиксируются при старте задачи; заявление DONE не подтверждает их. Непроверенные критерии блокируют успешное завершение очереди. Ручное подтверждение после завершения не возобновляет очередь автоматически.
2. Контекст: переключатели истории, памяти чата/проекта и сводки действий; бюджет истории 2–64 тыс. символов; до 12 закреплённых относительных файлов, до 32 КБ каждый, 64 КБ суммарно; пропуски отображаются. Предпросмотр нового контекста с черновиком без отправки и без вложений. Записываются длина и SHA-256 последнего реально выданного контекста.
3. Передача данных: запрет облачной пересылки, отдельное разрешение изображений/буфера, исключения файлов с * и **, дополнительное маскирование узнаваемых секретов. Запрет облака проверяется перед постановкой запроса и на реальных MCP-вызовах. Отключение истории/памяти блокирует и соответствующие инструменты чтения.
4. Журнал: версия приложения, источник Notion, режим, статусы, время, хеши запросов/результатов и размеры. Точное имя модели Notion недоступно и не выдумывается. По умолчанию аргументы и содержимое не записываются в новый журнал. Опциональная запись фрагментов имеет отдельное предупреждение, маскирование и лимит 64 тыс. символов на задачу. До 1 000 событий и 200 завершённых задач. Ошибка записи журнала не вызывает повторного выполнения действия.
5. Replay: просмотр и явный локальный экспорт записанных событий. Никакие команды, файлы, сеть или модель не запускаются. Это не детерминированное воспроизведение модели.
6. Git worktree: чистый корень репозитория, отдельная ветка и папка; чат переключается на копию, командные разрешения сбрасываются к подтверждениям. Для применения нужны проверенные коммиты, чистые папки и неизменённая основная ветка; только fast-forward. Нет автоматических git add/commit/stash/rebase. Удаление без force; ветка с коммитами сохраняется. Сессия Notion отзывается при смене копии — запустите пересылку заново.
7. Регрессионные тесты самого харнесса, включая запреты передачи, защиту критериев, сбои сборки контекста, безопасный replay и реальные операции Git.

## Где открыть

Локальный чат → Центр управления → Харнесс. Четыре раздела: критерии и доказательства; контекст и передача; рабочая копия; журнал и replay.

## Важные ограничения

- Это контроль инструментов, не песочница ОС. Shell-команда может обойти файловые исключения. Worktree не ограничивает доступ к остальному ПК; Git использует настроенные фильтры, хотя хуки в операциях менеджера отключены.
- Исключения не удаляют ранее сохранённые данные из истории и не отзывают переданное в Notion. Для будущей отправки отключите нужные разделы и начните новый разговор.
- Маскирование не является полной DLP и не анализирует текст внутри изображений. Некоторые служебные MCP-ответы маскируются независимо от переключателя.
- Бюджет истории не является общим лимитом контекста: память, системные сведения и вложения учитываются отдельно.
- SHA-256/наличие файла не доказывают его работоспособность. Код 0 доказывает успешный выход команды, не правильность тестов. Для независимого осмотра задайте ручной критерий.
- Старые журналы/чаты приложения имеют прежнее поведение хранения. Новый режим метаданных относится к журналу харнесса, не обещает очистки старых логов.
- Экспорт включает пользовательские критерии и примечания; проверьте их перед передачей. Диагностические фрагменты могут содержать нераспознанные чувствительные данные.
- Не реализованы новые модельные API, браузерная автоматизация, несколько ролей агентов, поиск по символам кода и сравнение моделей. Это следующие этапы, не скрытые заглушки.

## Сборка Windows

EXE 4.2.0-beta.1 собран и проверен на Windows. Полная проверка типов и Windows-runner прошли; готовый EXE проверен в headless-режимах установщика и приложения. Подробности, SHA-256 и ограничения — BUILD-WINDOWS.ru.md.

Файл в Загрузках: JarvisCodeSetup-4.2.0-beta.1.exe. Установленная версия не заменялась. EXE не подписан; автоматический источник обновлений не настроен.

Для повторной сборки используйте BUILD-INSTALLER.cmd или scripts/build-windows.ps1. Windows-runner явно исключает desktop.ts и ngrok.ts с Linux-специфичными фикстурами; это не полный bun run test и не нативная проверка установки/удаления.
